# SENSE+ v0.2 · 사용자 화면 및 PC 관제

**먼저 [빠른 시작](START_HERE_KO.txt)을 읽어 주세요.** 저장소를 받은 팀원은 `apps/sense-plus`에서 설치와 실행을 진행합니다.

이미 이 앱을 설치한 PC에서는 해당 가상환경을 재사용할 수 있습니다. 새 PC에서는 설치 스크립트가 이 앱 전용 `.venv`를 생성합니다.

- PC 관제: `http://127.0.0.1:8766` (기본 실행 시 자동 열림)
- PC 사용자 웹앱 테스트: `http://127.0.0.1:8765`
- 실제 스마트폰: `start_phone_windows.bat` 또는 `start_phone_mac.command`를 실행하고 [iPhone 연결 절차](#iphone-인증서-설치와-연결)에 따라 인증서를 설치한 뒤 관제 QR을 스캔합니다.
- 로컬 음성 모델을 설정하면 **카메라·마이크로 시작**으로 주변 확인과 “헤이 센스” 질문을 함께 시작할 수 있습니다. 빨간 **안내 종료**를 누르면 카메라와 마이크 연결이 끝납니다. 물건 찾기와 정보 읽기는 **다른 기능**에서 엽니다.
- 휴대폰 카메라는 30fps를 목표로 요청합니다. PC는 실제 수신 FPS를 계산하고, AI 요청을 받으면 흔들림이 적고 윤곽이 충분한 최신 프레임 한 장을 자동으로 선택합니다. 제한 시간 안에 선택하지 못하면 이유를 알리고 분석을 보류합니다. 관제의 **자동 미리보기**는 선택해서 켤 수 있습니다.
- 관제는 수신 해상도, FPS, 프레임과 변환 오디오 샘플 수, 질문 음성 RMS와 진폭 파형, 영상·음성의 서버 도착차, 세션 ID·질문 ID·응답 ID, AI 처리시간을 표시합니다. AI 요청에 들어간 프레임 번호와 수신 시각, 재생 음성의 출처도 확인할 수 있습니다. 최근 400개 메타데이터 이벤트는 검색·유형 필터·CSV 내보내기를 지원합니다. 관리자는 루프백에서만 접속할 수 있습니다.
- Windows에서는 설치한 Ollama 영상 모델에 안정 프레임과 한국어 Whisper 질문을 보내고, Windows 한국어 음성으로 답변을 합성합니다. 모델 설정과 팀 모듈 교체 규격은 [통합 문서](docs/INTEGRATION.md)에 있습니다.
- 검증 범위와 미검증 사항: `TEST_STATUS.md`.

카메라 화면이 보이는 것, 서버가 영상을 받는 것, AI가 장면을 이해하는 것은 서로 다른 단계입니다. 이 프로젝트는 화면에 연결 상태를 구분해서 표시합니다. 디자인 시연의 예시 안내와 서버 확인음은 실제 인식 결과가 아닙니다.

## 1. Windows에서 시작하기

필요한 것: **Python 3.11 또는 3.12**, 카메라·마이크가 있는 PC, 처음 설치할 때의 인터넷 연결. 별도로 Node.js를 설치할 필요는 없습니다.

1. 저장소를 내려받고 `apps/sense-plus` 폴더를 엽니다.
2. `setup_windows.bat`를 더블클릭합니다. 처음 한 번만 실행하면 됩니다.
3. `설치 완료`가 보이면 창을 닫고 실행 파일을 고릅니다. **iPhone 연결 및 QR**은 `start_phone_windows.bat`, **PC 단독 시험**은 `start_windows.bat`를 더블클릭합니다.
4. PC 관제가 자동으로 열리지 않으면 브라우저 주소창에 `http://127.0.0.1:8766/`을 직접 입력합니다. PC에서 사용자 앱을 시험할 주소는 `http://127.0.0.1:8765/`입니다.

설치 파일은 이 폴더 안의 `.venv`라는 독립 Python 환경에 필요한 패키지만 설치합니다. 관리자 권한, 재부팅, Python 자동 설치, 유료 AI 호출은 수행하지 않습니다. Python이 없거나 버전이 다르면 설치를 멈추고 안내합니다.

Python을 수동으로 설치해야 한다면 [Python 공식 다운로드](https://www.python.org/downloads/)에서 3.12 또는 3.11을 선택하세요. 설치 후 `setup_windows.bat`를 다시 실행합니다.

**서버를 켠 터미널 창은 실행 중 계속 열어 두세요.** PC 단독 시험에서 휴대폰 모드로 바꾸려면 그 창에서 `Ctrl+C`를 누른 뒤 `start_phone_windows.bat`를 실행합니다.

## 2. Mac에서 시작하기

Python 3.11 또는 3.12가 필요합니다. `apps/sense-plus` 폴더에서 아래 순서로 실행합니다.

1. `setup_mac.command`를 실행합니다.
2. iPhone 연결 및 QR은 `start_phone_mac.command`, PC 단독 시험은 `start_mac.command`를 실행합니다.
3. PC 관제가 자동으로 열리지 않으면 브라우저 주소창에 `http://127.0.0.1:8766/`을 직접 입력합니다.

더블클릭 실행이 안 되면, 해당 폴더에서 터미널을 열고 다음 명령으로 실행할 수 있습니다.

```bash
bash setup_mac.command
bash start_mac.command
```

이 명령은 시스템 보안 설정을 해제하지 않습니다. 다른 Mac이나 다른 위치로 옮겼을 때 기존 `.venv`는 함께 복사하지 말고 새 위치에서 설치 파일을 다시 실행하세요.

## 3. 처음 확인할 순서

휴대폰에서는 PC 관제의 새 QR을 스캔해 앱을 엽니다. 로컬 음성 모델이나 음성 기능을 지원하는 팀 AI 서버가 연결되어 있으면 카메라·마이크 권한을 확인하고 PC에 자동으로 연결합니다. 처음 뜨는 브라우저 권한 창에서 카메라·마이크를 허용해 주세요. 브라우저가 소리 자동 재생을 제한해도 영상과 화면 안내가 시작됩니다. 소리는 같은 연결에서 **음성 안내 시작**을 한 번 눌러 켭니다.

1. “센서 플러스가 실행되었습니다”가 들리면 카메라에 잡힌 주변을 자동으로 설명합니다.
2. 안내 음성이 끝난 뒤 “헤이 센스, 내 앞에 뭐가 있어?”처럼 한 문장으로 질문합니다. 호출어만 먼저 말했으면 화면에 질문을 듣고 있다는 상태가 표시된 뒤 이어서 말하세요.
3. 말이 끝나면 앱이 안정 프레임과 질문을 분석해 답하고, 재생이 끝나면 주변 확인을 이어갑니다.
4. **안내 종료**로 카메라와 마이크를 끕니다. 버튼으로 질문하려면 **음성 질문 → 말하기 완료**를 사용하세요.

호출어 대기 중에는 마이크 입력이 WebRTC로 이 PC에 전송됩니다. 팀 AI 서버를 연결한 경우 말소리가 감지된 구간을 팀 서버로 보내 호출어를 확인합니다. 이때 팀 서버가 설정한 외부 음성 API에도 해당 구간이 전달될 수 있습니다. 앱은 음성 구간이나 전사문을 저장하지 않습니다. **설정 → 헤이 센스 음성 질문**에서 호출어 사용을 끌 수 있습니다.

수신 수치와 확인음은 **설정 → 연결 상태**에서 확인할 수 있습니다. 가상 화면은 **설정 → 카메라 미리보기와 시연 → 디자인 시연**에서 엽니다.

| 순서 | 확인할 것 | 확인되는 범위 |
|---|---|---|
| 1 | 화면과 버튼이 잘 보이는가 | 웹 UI |
| 2 | 카메라를 켜면 실제 주변 영상이 보이는가 | 브라우저의 카메라 권한과 로컬 미리보기 |
| 3 | 실시간 연결 후 서버 수신 프레임 수가 늘어나는가 | 카메라 영상이 FastRTC 서버에 도착함 |
| 4 | 질문 중 서버 음성 수신 수치가 늘어나는가 | 음성 데이터가 서버에 도착함. 말뜻 이해까지 확인한 것은 아님 |
| 5 | 서버 확인음을 요청하면 짧은 소리가 들리는가 | 서버 → 브라우저 음성 전송과 재생 |
| 6 | 로컬 모델 또는 팀 서버를 설정한 뒤 장면 질문에 답하는가 | 모델·STT·TTS 연동 |

기본 설정은 `AI 미연결` 상태에서 영상과 음성 전송을 시험할 수 있습니다. 모델을 켜려면 아래 모델 연결 절차를 따릅니다. 디자인 시연은 화면 구성을 보여주는 별도 기능입니다.

마이크가 꺼진 상태에도 WebRTC가 무음 패킷을 보낼 수 있습니다. 따라서 음성 패킷 수만으로 목소리 녹음이나 음성 인식 성공을 판단하지 않습니다. 질문 구간, 실제 입력 레벨, 팀 AI의 인식 결과를 함께 확인해야 합니다.

## 4. 추가 패키지 설치 없이 화면만 보기

Python이 이미 있다면 FastRTC를 설치하기 전에 UI만 확인할 수 있습니다.

Windows에서 Python 3.12를 사용하는 경우:

```powershell
py -3.12 preview.py --open-browser
```

Python 3.11을 사용한다면 `-3.12` 대신 `-3.11`을 사용합니다. Mac에서는:

```bash
python3 preview.py --open-browser
```

이 실행 방식은 화면 파일과 `/api/health`만 제공합니다. **실시간 서버 연결, AI 분석, 서버 확인음은 제공하지 않습니다.** 화면에는 미리보기 상태가 표시됩니다.

이미 설치한 독립 환경을 이용해도 됩니다.

```powershell
.venv\Scripts\python.exe run.py --ui-only --open-browser
```

```bash
.venv/bin/python run.py --ui-only --open-browser
```

## 5. 실제 스마트폰 연결

GitHub에는 앱 소스와 실행 안내가 있습니다. 수업에서 iPhone으로 앱을 시험하려면 **SENSE+를 실행 중인 PC와 같은 Wi-Fi**에 연결하고 그 PC의 관제 QR을 사용합니다. PC 관제 주소 `127.0.0.1:8766`은 시연 PC에서 엽니다.

### iPhone 인증서 설치와 연결

**[수업 시연용 `SENSE-test-root.cer` 다운로드](docs/certificates/SENSE-test-root.cer?raw=true)**

이 파일은 현재 시연 PC `192.168.40.142`가 쓰는 공개 시험용 인증서예요. 인증서는 **2026년 12월 4일 오전 10시 20분(KST)**까지 유효합니다. 시연 PC가 바뀌거나 시연 담당자가 인증서를 갱신했다면 그 PC에서 새로 받은 파일을 사용해 주세요.

1. **iPhone에서 인증서 열기.** Safari에서 위 다운로드 링크를 누릅니다. 파일만 저장되고 프로파일 다운로드 안내가 뜨지 않으면, 시연 담당자에게 같은 `.cer` 파일을 메일로 받아 iPhone 기본 **Mail** 앱에서 첨부 파일을 열어 주세요. [Apple의 인증서 배포 방법](https://support.apple.com/ko-kr/guide/deployment/depcdc9a6a3f/1/web/1.0)
2. **설정에서 설치하기.** iPhone **설정**을 열고 상단의 **프로파일이 다운로드됨 → 설치**를 누릅니다. 항목이 사라졌으면 파일이나 메일 첨부를 다시 연 뒤 바로 설정으로 들어갑니다. 설치된 프로파일은 **설정 → 일반 → VPN 및 기기 관리**에서 확인합니다. [Apple의 프로파일 설치 안내](https://support.apple.com/en-us/102400)
3. **해당 인증서 신뢰하기.** **설정 → 일반 → 정보 → 인증서 신뢰 설정**으로 갑니다. **루트 인증서 전체 신뢰 활성화** 아래에서 `SENSE+ TEST ONLY 192.168.40.142`만 켭니다. 새 파일을 받았다면 시연 담당자가 알려 준 PC 주소와 인증서 이름을 맞춰 봅니다. [Apple의 인증서 신뢰 안내](https://support.apple.com/ko-kr/102390)
4. **같은 Wi-Fi에서 QR 찍기.** iPhone 기본 카메라로 PC 관제 화면의 QR을 찍어 Safari로 엽니다. 권한 요청이 뜨면 카메라·마이크를 허용합니다. 자동 시작을 제한하는 브라우저에서는 화면의 시작 버튼을 사용합니다. PC 서버를 다시 켰다면 관제 화면에서 새 QR을 찍습니다.

**시연 PC에서 준비하는 법**

기존 SENSE+ 서버가 켜져 있으면 해당 터미널에서 `Ctrl+C`를 누릅니다. `apps/sense-plus`에서 Windows는 `start_phone_windows.bat`, Mac은 `start_phone_mac.command`를 실행합니다. Windows 터미널에서는 `무선 LAN 어댑터 Wi-Fi`의 IPv4 주소를 찾아 입력합니다. PC 관제 주소는 `http://127.0.0.1:8766/`입니다. QR은 휴대폰 모드 서버가 시작되면 표시됩니다. 다른 PC에서 시연할 때는 그 PC의 터미널에 표시된 `phone-certs/<PC의 IPv4>/SENSE-test-root.cer`를 전달합니다. `server-key.pem`은 해당 PC에 보관합니다.

**연결이 막힐 때**

- Safari에 인증서 경고가 뜨면 프로파일 설치와 전체 신뢰를 다시 확인합니다. PC 주소가 바뀌거나 시험용 인증서가 갱신됐다면 현재 시연 PC에서 다시 받은 파일과 새 QR을 사용합니다.
- 페이지가 열리지 않으면 PC 서버와 같은 Wi-Fi에 연결돼 있는지 확인합니다. 교육장 게스트 Wi-Fi는 기기끼리의 접속을 차단할 수 있습니다.
- 학교에서 관리하는 iPhone의 프로파일 설치가 제한돼 있으면 수업 담당자에게 문의합니다. 시험이 끝나면 **설정 → 일반 → VPN 및 기기 관리**에서 이번에 추가한 SENSE+ 시험용 프로파일을 제거합니다. [Apple의 프로파일 제거 안내](https://support.apple.com/ko-kr/guide/iphone/iph6c493b19/ios)

### 기존 인증서로 직접 실행

인증서 도구로는 [mkcert 공식 프로젝트](https://github.com/FiloSottile/mkcert)를 참고할 수 있습니다. 아래는 **문서 예시**이며 설치 스크립트가 실행하지 않습니다. `192.168.0.23`은 실제 PC IP로 바꿉니다.

```bash
mkcert -cert-file cert.pem -key-file key.pem 192.168.0.23 localhost 127.0.0.1 ::1
```

별도로 발급한 서버 인증서를 쓰려면 iPhone에 공개 CA 인증서를 설치하고 신뢰를 켭니다. 서버 인증서와 개인키는 `frontend` 폴더 밖에 둡니다.

Windows 실행 예시:

```powershell
.venv\Scripts\python.exe run.py --host 192.168.0.23 --cert "C:\sense-certs\cert.pem" --key "C:\sense-certs\key.pem"
```

Mac 실행 예시:

```bash
.venv/bin/python run.py --host 192.168.0.23 --cert "/Users/yourname/sense-certs/cert.pem" --key "/Users/yourname/sense-certs/key.pem"
```

실행한 뒤에는 PC에서 관제 화면을 열고 휴대폰으로 새 QR을 스캔합니다. 예시의 `192.168.0.23`을 시연 PC의 사설 IPv4로 바꿔 사용합니다.

기본 실행은 PC 내부에서만 연결됩니다. 이 패키지는 자동 공개 배포·포트 포워딩·터널 생성을 하지 않습니다. 같은 Wi-Fi에서도 실제 연결은 방화벽과 네트워크 조건을 확인해야 합니다. Wi-Fi가 서로 다르거나 이동통신망을 사용하려면 WebRTC 담당자가 STUN/TURN 및 접근 제어를 별도로 구성해야 합니다.

## 6. 모델 연결

Windows에서 로컬 영상·음성 모델을 쓰려면 [Windows 로컬 모델](docs/INTEGRATION.md#windows-로컬-모델) 절차를 따릅니다. 아래 설정은 팀이 별도 HTTP 분석 서버를 제공할 때 사용합니다.

1. `.env.example`을 같은 폴더에 `.env`라는 이름으로 복사합니다.
2. `SENSE_AI_URL`에 팀 AI 서버의 **전체 POST 주소**를 적습니다.
3. 팀 AI 서버가 인증 키를 요구할 때만 `SENSE_AI_KEY`를 적습니다.
4. SENSE+ 서버를 종료했다가 다시 실행합니다.

예시:

```dotenv
SENSE_AI_URL=http://127.0.0.1:9000/analyze
SENSE_AI_KEY=
```

`SENSE_AI_URL`은 OpenAI 등 제공자의 주소를 아무렇게나 넣는 칸이 아닙니다. **이 프로젝트의 요청·응답 규격을 구현한 팀 AI 서버 주소**입니다. STT, 장면 이해, 물건 찾기, 글자 읽기, TTS를 어느 모델로 할지는 팀 서버 쪽에서 구현합니다.

팀 서버로 QR 자동 연결을 쓰려면 저장소 루트에서 `python -m uvicorn api_server:app --host 127.0.0.1 --port 9000`으로 팀 AI 서버를 먼저 켭니다. 이후 `apps/sense-plus`에서 SENSE+ 휴대폰 모드를 다시 시작합니다. 사용자 앱의 HTTPS 주소 뒤에 `/api/health`를 붙여 `voice_wake_available: true`와 `voice_wake_provider: "team-api"`를 확인한 뒤 관제 화면의 새 QR을 스캔합니다.

실제 규격은 [docs/INTEGRATION.md](docs/INTEGRATION.md)에 있습니다. 팀 서버에서 유료 API를 사용하도록 구성한다면 그 비용과 사용 권한은 별도로 확인해야 합니다. 이 패키지의 기본 설정은 모델 다운로드나 유료 AI 호출을 하지 않습니다.

## 7. 영상과 질문을 맞추는 방식

버튼 질문은 서버가 최신 안정 프레임을 선택한 뒤 녹음을 시작합니다. 호출어 질문은 발화에서 질문을 분리한 뒤 최신 안정 프레임을 선택합니다. 각 경로는 질문과 프레임을 같은 `turn_id`로 묶습니다. 버튼으로 질문을 끝내면 기본 300ms 동안 늦게 도착한 음성을 더 받습니다. 영상이 끊기면 분석을 보류합니다.

이는 **질문과 장면이 엇갈리는 것을 줄이기 위한 구현**입니다. 카메라 원본 촬영 시각과 음성 샘플을 완벽하게 맞춘 정밀 동기화는 아닙니다. 서버와 실제 휴대폰에서 지연을 측정하고 조정해야 합니다.

질문은 최대 20초까지 모으며 화면에서도 20초가 되면 자동으로 질문을 마칩니다. 짧게 질문한 뒤 `말하기 완료`를 눌러도 됩니다. 이전 요청이 취소되거나 모드가 바뀐 뒤 도착한 응답은 현재 결과를 덮어쓰지 않도록 구분합니다.

## 8. 자주 만나는 문제

| 증상 | 먼저 확인할 것 |
|---|---|
| 설치 파일을 눌러도 실행이 안 됨 | ZIP을 전부 풀었는지, Python 3.11/3.12가 설치되어 있는지 확인 |
| `Python 3.11 또는 3.12를 찾지 못했습니다` | 필요한 Python 버전을 설치한 뒤 설치 파일 재실행. 스크립트는 Python을 자동 설치하지 않음 |
| 패키지 설치 중 네트워크 오류 | 인터넷·기관 프록시·패키지 다운로드 제한을 확인. 오류가 난 단계의 문구 보존 |
| 페이지를 찾을 수 없음 | 서버 터미널이 열려 있는지 확인. 로컬 주소는 `http://127.0.0.1:8765` |
| 포트를 열 수 없음 | 기존 서버를 종료하거나 `.venv\Scripts\python.exe run.py --port 8775 --admin-port 8776 --open-browser` 사용. Mac은 실행파일을 `.venv/bin/python`으로 변경 |
| PC 관제에 QR이 안 보임 | 관제에 `PC 단독 모드`가 표시되면 기존 SENSE+ 창에서 `Ctrl+C`를 누른 뒤 `start_phone_windows.bat` 또는 `start_phone_mac.command`를 실행. 그 PC의 Wi-Fi IPv4를 입력하고 `http://127.0.0.1:8766/`을 주소창에서 다시 열기 |
| 카메라 권한이 안 뜸 | 로컬 PC에서는 localhost/127.0.0.1, 휴대폰에서는 신뢰되는 HTTPS인지 확인 |
| 카메라가 검게 보임 | 다른 프로그램이 카메라를 사용하는지, 브라우저의 사이트별 권한이 거절되었는지 확인 |
| 영상은 보이는데 서버 수치가 늘지 않음 | 로컬 미리보기와 서버 연결을 구분. `preview.py`가 아닌 `run.py`로 실행했는지 확인 |
| 서버 확인음이 안 들림 | 휴대폰 음량·출력 장치, 음성 출력 버튼, 브라우저 재생 허용을 확인 |
| 답변 글자는 보이는데 음성이 안 들림 | 웹앱의 **설정 → 음성 안내**가 켜져 있는지 확인하고 답변 아래의 **음성 재생** 또는 **다시 듣기** 누르기. PC 관제의 **답변 음성**에서 Windows 한국어 합성 또는 휴대폰 합성 경로 확인 |
| `AI 미연결` | 기본 통신 시험 상태. 로컬 모델이나 팀 분석 서버를 `.env`에 설정한 뒤 서버 재시작 |
| 폴더를 옮긴 뒤 실행 안 됨 | `.venv`는 PC·경로 간 휴대용이 아님. 해당 폴더의 `.venv`만 제거한 뒤 설치 파일 재실행 |
| 휴대폰에서 화면은 열리지만 실시간 연결 실패 | 같은 Wi-Fi, 기기 간 통신 차단, 방화벽, ICE 설정을 차례로 확인 |

## 9. 팀원에게 전달하기

팀원은 이 저장소의 앱 소스를 내려받아 자기 PC에서 설치 스크립트를 실행합니다. 아래 파일은 각 PC에서 별도로 관리합니다.

- `.venv`, `venv`, `__pycache__`, 캐시·빌드 폴더
- `.env`, API 키, 세션 토큰, 서버 인증서 개인키, 모델 가중치. 이 저장소에 포함된 수업용 `.cer`는 공개 인증서입니다.
- 촬영 이미지·녹음 파일·개인정보가 포함된 로그
- 테스트에서 임시로 생성한 산출물

이 서버는 카메라·질문 데이터를 처리 중 메모리에 둡니다. 디스크 녹화 기능은 포함하지 않습니다. 팀 AI 서버의 보관 정책은 그 서버에서 따로 정해야 합니다.
